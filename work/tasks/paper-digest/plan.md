# 计划（草案）· 子代理读文献 + 本地省 token

> 状态：待确认。前置：`paper-page` 技能、`tools/page2md.py`（M1/M2 已实现）。
> 约束：**不接任何第三方 API**（Europe PMC / Semantic Scholar / Jina 等一律不用），全部本地、离线可跑。

## 1. 要解决的问题

1. 一篇 Elsevier 论文转出来 ~9.1 k tokens（已去掉参考文献、已去重、已分节），主代理**不能整篇读**。
2. 文献调研要读 10+ 篇，主上下文必然爆。
3. 省 token 不能靠"压缩改写"，否则 AI 会丢掉它需要引用的东西。

## 2. 决策：三层分离，各管一件事

| 层 | 做什么 | 谁来做 | 上下文成本 |
|---|---|---|---|
| **L1 抽取** | 网页 → 结构化 Markdown（分节、公式、表格、图） | `tools/page2md.py`（本地规则，零模型） | 0 |
| **L2 选读** | 给"地图"（每节讲什么、多少钱）+ 任意门（按节/段检索） | `page2md` 新增 `gist`/关键词/段落编号/`--query`/`--slice` | 地图 ~300 tok |
| **L3 消化** | 读原文、产出**带出处的结构化摘要** | **子代理**（独立上下文，读完即弃） | 主代理只收 ~1.2 k tok |

关键点：**子代理读的是原文，不是摘要的摘要**；它输出的每一条都带 `where`（节号+段号），主代理需要核对时只取那一段（`--slice`），形成闭环。

## 3. 被否的替代方案

- **接 Europe PMC/JATS/Semantic Scholar**：质量最好，但用户明确不接第三方接口。否决（保留为将来的可选源）。
- **本地小模型做摘要**：要下载权重、要 GPU/CPU 推理时间，且结论不可复现。否决。
- **只给主代理 `page.core.md`（2.3 k）**：省，但方法/数据细节全丢，问细节就得重读整篇。仅作兜底。
- **把整篇塞进子代理再让它写一段话总结**：无出处、无法核对，等于把幻觉风险放大。否决。

## 4. L2 具体改动（`tools/page2md.py`）

1. `index.json` 每节增加：`gist`（前 2 句 + 含数字的句子 + 末句，≤160 字符）、`keywords`（TF top-8，无模型）、`paragraphs`（段数）、`tokens`（已有）。
2. 正文每段前加稳定编号注释 `<!-- p12 -->`（不影响阅读），供 `--slice` 精确定位。
3. 新参数：
   - `--query "topology optimization"` → 只输出命中段落 ±1 句，输出 `[p12] …`；
   - `--slice 12:30` → 按段号取区间；
   - `--brief` → 生成 `page.brief.md`（标题/作者/摘要/结论要点，~400 tok）。
4. 有损操作一律关：图注、表格、公式的长内容**默认保留**；需要压缩时用 `--compact-figures|--compact-tables|--compact-math` 显式打开，并在 `meta.json` 写 `compressed: [...]`。

## 5. L3 子代理协议（写进 `paper-page` 技能）

主代理只做三件事：拿 `index.json` → 派子代理 → 收 `digest.json`。

子代理输入：`index.json` + 允许它自己 `read` 任意 `sections/*.md`。
子代理必须输出（严格 JSON，≤1.5 k tokens）：

```json
{
  "title": "", "doi": "", "year": "",
  "problem": "一句话：解决什么问题",
  "method": "3–5 句：怎么做（关键思路+手段）",
  "key_numbers": [{"value": "0.87", "meaning": "转化率", "where": "sections/07-3.1-....md#p4"}],
  "conclusions": ["…（每条 ≤80 字）"],
  "figures": [{"label": "Fig. 3", "says": "…", "where": "sections/07-....md"}],
  "sections": [{"title": "3.1 …", "topic": "一句话", "tokens": 1769, "worth_reading": true}],
  "uncertain": ["读不准或页面缺内容的地方"],
  "fidelity_warnings": ["从 meta.json 抄来的告警"]
}
```

纪律（写进技能，违反即视为失败）：
1. `key_numbers` 必须逐字来自原文，禁止换算/推算；找不到出处就写进 `uncertain`；
2. 每条结论都要能在 `where` 指到的位置找到原句；
3. 页面 `fidelity_warnings` 非空且问题涉及公式/表格时，摘要里要写明"此处建议看 PDF"；
4. 子代理不写文件、不改仓库，只返回 JSON。

## 6. 批量调研（10+ 篇）

用 `workflow` 脚本对每篇跑一条独立流水线：`agent(读一篇 → digest.json)`，并发 3–4 条；主代理只收 N 份 JSON（每份 ≤1.5 k），
再自己合成综述。**主上下文与篇数近似线性于 JSON 大小，而不是全文大小**。

## 7. 里程碑与验收

| 阶段 | 交付 | verify |
|---|---|---|
| M1 | `index.json` 增 `gist`/`keywords`/段落编号；`--query`、`--slice`、`--brief` | 单测：gist 取句规则、query 命中窗口、slice 边界；真机 MHTML 跑一遍看 token 数 |
| M2 | 技能补"子代理协议"与主代理三种用法（初筛/问答/综述） | 用同一篇论文跑 10 问：仅凭 digest 作答 vs 读全文作答，答案一致率 ≥9/10 |
| M3 | 批量：`workflow` 脚本模板 + 并发/失败重试策略 | 5 篇实测：主上下文增量 ≤8 k tokens，digest 全部通过出处核对 |

**不达标就不上线**：一致率 <9/10 或 digest 出现无出处的数字，视为失败。

## 8. 预期效果（同一篇 Elsevier 论文实测基线）

| 场景 | 现在 | 方案后 |
|---|---|---|
| 了解论文讲了什么 | 9.1 k（全文） | `index.json` + gist ≈ **0.4 k** |
| 写结构化摘要 | 9.1 k | 子代理 digest ≈ **1.2 k**（主上下文） |
| 回答"图 3 说明了什么" | 需读整篇 | 子代理或 `--slice` 单段 ≈ **0.2–0.5 k** |
| 调研 10 篇综述 | 90 k+ | **12–15 k**（10 份 digest） |
