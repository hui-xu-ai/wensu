# 0020 · 一次导出读一段记录（替代"用排除法深入"）

**状态**：已接受并实现（2026-11-22，0.14.0）
**相关**：ADR 0005（配额）、ADR 0019（页面通读）、`docs/adr/0013-*`（版本）

## 背景

Web of Science 渠道在 `www.webofscience.com` 上不通过页面 `fetch` 拿数据，而是点站点的
「导出 → BibTeX」，把下载到的 `.bib` 解析成记录（`plan_export.py` + `parse_bibtex.py`）。

导出对话框打开时默认选的是「页面上的所有记录」，也就是**当前结果页的 50 条**。为了读到第
51 条以后，内核提供了一个 `exclude_ut` 参数：把已拿到的 UT 传回去，站点返回剩下的（契约上限
500 个 UT）。于是"读 1000 条"意味着 **20 次完整检索**：每次都是导航 → 输入检索式 → 提交 →
4 次导出点击，还得自己维护已读集合。

这条路线有两个问题：

1. **对站点更重**。20 次完整检索的导航量，远大于 1 次检索 + 1 次导出；
2. **本来不需要**。站点的导出对话框自带"记录: [起] 至 [止]"范围，Clarivate 明确写着完整记录
   **一次最多 1000 条**（[Limit on exporting](https://supportcenter.clarivate.com/s/article/Web-of-Science-Limit-on-exporting?language=en_US)；
   含引文参考文献时 500）。

## 决定

`search` 增加两个参数（不新增动词、不新增工具）：

- `records_from`（1 起，含）/ `records_to`（含），合起来就是一次导出要读的记录区间；
- 与 `page` **互斥**：范围已经说明了读哪一段，翻页是另一种读法；
- 单次最多 **500 条**（见下"后果"第 3 条）；
- 只有读导出文件的渠道支持（WoS 全球站）；其他渠道明确报错，不静默退回 50 条。

读下一段是 **`records_from=501`**，不是新的检索，也不再需要 `exclude_ut` 来"深入"。

### 站点控件（2026-11-22 真实观测，不是猜的）

导出对话框（`app-export-out-details form`）：

| 控件 | 选择器 | 说明 |
|---|---|---|
| 范围单选（默认"页面上的所有记录"） | `#radio3-input`（`value="fromRange"`） | 选中后才解锁下面两个数字框 |
| 起 | `input[name="markFrom"]`（`min=1`，`aria-label="输入开始记录范围"`） | 选中前是 `disabled` |
| 止 | `input[name="markTo"]` | 同上 |

实测样本存于 `work/scratch/wos-export-dialog.html`（本地，不入库）。

## 后果

1. **配额不变**：一次导出仍按一次网络动作计费，但一次拿到 500 条（此前 50 条/次）。
2. **`exclude_ut` 降级为"过滤"**：留作隐藏已知记录用，不再是深入的手段。文档与工具描述同步改写。
3. **单次上限取 500，不是 1000**：实测（同日，同一检索式）请求 500 条时文件按时到达、解析出
   500 条记录、全程 59.8 s；请求 1000 条时**没有产生文件** —— 单动作等待下载的预算是 15 s，
   更大的导出赶不上。要突破这条就得放宽单动作超时（`MAX_TIMEOUT_MS`），那是另一份 ADR。
4. **`total` 在范围读时为 `null`**：导出文件只说明"带了多少条"，不说明"检索命中多少条"。
   以前把"本页条数"当 `total` 已经不准；1000 条时更会被读成"这个主题只有 500 篇"。
   宁可留空，也不给错的数。
5. **响应体变大**：500 条完整记录是 MB 级。`include_abstract` 默认 false，`fields` 可进一步投影；
   调用方要正文时用 `detail(url)`，命中缓存不花额度。

## 被否的替代方案

- **提高 `limit` 到 1000**：`limit` 是"一页最多取几条"的语义，CNKI 也用它（20/50）。
  混进"导出范围"会把两种读法搅在一起，还会绕过 `MAX_LIMIT` 的既有含义。否决。
- **保留 `exclude_ut` 作为深入手段**：见背景第 1、2 条。否决（参数保留，但不再是深入手段）。
- **在一次调用里连做两次导出（500+500）**：可以做到 1000 条/次，但一个计划里两次下载、
  两次对话框，失败面翻倍、计划时长逼近上限。留作后续选项，先不做。
