# 0015 · 把 `type` 动作的文字上限从 500 字符放宽到 16000

**状态**：已接受（2026-11-10）
**相关**：ADR 0014（计划预算 120 s → 200 s，同类问题）

## 背景

`AGENTS.md` 规定硬限制原则上只能收紧，放宽必须新增 ADR。这是那份 ADR。

`core/params.py` 的 `MAX_TEXT_CHARS = 500` 限制单个 `type` 动作能携带的文字量。

0.12.42 引入 `exclude_ut` 后，两个上限互相矛盾：

| 常量 | 值 | 含义 |
|---|---|---|
| `MAX_EXCLUDE_UT` | 500 | 一次检索最多排除多少个 WoS 号 |
| `MAX_TEXT_CHARS` | 500 | 一个 `type` 动作最多能输入多少字符 |

WoS 的排除表达式每多一个号约增加 25 个字符：

```
排除   3 个 →    197 字符
排除  17 个 →    547 字符   ← 刚好越过 500
排除  50 个 →  1 372 字符
排除 500 个 → 12 622 字符
```

**所以实际有效上限是 17 个**，而参数声明是 500。测试时用 3 个号（197 字符）通过，
按文档规模使用时被内核自己的参数校验拒绝：

```
wensu: invalid parameters for type: policy.params
```

这次失败消耗 0 配额、1.6 秒，属于**好失败**——但它是我的不一致造成的，不是站点的问题。

## 决定

`MAX_TEXT_CHARS` 从 **500 改为 16000**。

`MAX_EXCLUDE_UT` 保持 500（12 622 字符 + 主体表达式，16000 留有余量）。

## 理由

**这个上限不是打字速度预算。** `humanType` 的实现是：

```js
element.value = text;                      // 一次性赋值
element.dispatchEvent(new Event("input"));
element.dispatchEvent(new Event("change"));
```

**站点看到的是粘贴，不是 12000 次按键。** 所以放宽它不改变任何与"拟人"或风控有关的性质，
只改变"标签页最多被喂多长的字符串"。

**16000 而不是无限**：它仍然是上限，一个计划依然不可能把任意长的文本塞进输入框。

## 后果

- `exclude_ut` 现在能按声明的规模工作：50 个号 1 372 字符，500 个号 12 622 字符。
- 所有渠道的 `type` 上限一起放宽。这没有引入新的风险面：`type` 是写入一个输入框，
  不产生网络请求，`type` 也不在 `NETWORK_VERBS` 里。
- 新增一条一致性测试：`MAX_EXCLUDE_UT` 个排除号生成的表达式必须能通过 `type` 的参数校验。
  **这次的问题正是"两个上限各自看起来都合理，合起来不成立"，只有一条跨常量的断言能挡住它。**

## 被否的选项

**把 `MAX_EXCLUDE_UT` 降到 17。** 拒绝：那会让排除法只能覆盖一页多，而整个功能的目的
就是用独立请求代替连续翻页去走深层结果。降上限等于取消功能。

**按渠道给 `MAX_TEXT_CHARS` 开口子。** 拒绝：同类问题（ADR 0014 只提 WoS 预算）已经
论证过一次——内核级约束按渠道开口子会让"有界"这件事失去意义。
