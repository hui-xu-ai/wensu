# 0016 · 全球站用 BibTeX 导出取数，影响因子改由本地 JCR 库提供

**状态**：已接受（2026-11-11）
**取代**：ADR 0007（WoS 用捕获响应流取数）中"所有 WoS 站点都走捕获"的适用范围
**触发**：`www.webofscience.com` 上 `runQueryGetRecordsStream` 无法被内容脚本捕获

## 背景

镜像站 `webofscience.clarivate.cn` 的取数依赖 `capture.js` 在顶层窗口 hook
`window.fetch` 与 `XMLHttpRequest`，拦截 `runQueryGetRecordsStream` 的 NDJSON 流（ADR 0007）。

在 `www.webofscience.com` 上这条链路不成立：`data-wensu-seen` 记录了该页面经过
fetch/XHR 的**全部**请求路径（23 个），其中没有任何 `runQuery*` 端点——请求由我们
覆盖不到的上下文发出。多次尝试（扩大前缀、调等待窗口、改注入时机）都只改变了失败
的表现形式，没有改变"看不到请求"这个事实。

而该站点**自带 BibTeX 导出**，且下载功能只在 `.com` 提供（镜像站不提供，正好避免违规下载）。

## 决定

1. **按站点取数**：`.com` 走 BibTeX 导出，镜像站保持现有捕获路径。由
   `plan_search.EXPORT_HOSTS` 判定，不新增调用方参数。
2. **导出计划**只替换检索的"后半段"，前半段（打开检索页、输入、提交）与捕获路径共用。
3. **条目键即 UT**：`@article{ WOS:001218812900001,` ⇒ `url = DETAIL_PREFIX + ut`，
   `detail`、`exclude_ut`、导出格式与两种取数路径解耦。
4. **影响因子来自本地库**：`wensu jcr import <xlsx>` 把用户自备的 JCR 表建成
   `$HOME/data/jcr.sqlite`；**数据不随包分发**。
5. **下载路径由扩展回报**：`click` 的新参数 `expect_download` 让扩展把完成的下载文件
   路径放进 `data.download`。**不新增第十个动词**。

## 理由

- **导出是站点公开功能**，不是内部接口；BibTeX 有规范，可离线回放测试，站点改版时
  坏的是选择器而不是格式。
- **数据比接口更全**：真实样本 39 条中 DOI、摘要各 39/39，另含 `Times-Cited`、`ISSN`。
- **JCR 数据授权归 Clarivate**，打进 wheel 是越权；4.2 MB 的表每年更新一次，本地建库
  正好把"更新"变成一条命令。
- **`expect_download` 挂在现有动词上**，因为导出这个动作本来就发生了，文件是它的结果；
  为它新增动词会破坏"词汇封闭"这条不变量（ADR 0002/0005 的同一考虑）。

## 被否的替代方案

| 方案 | 否决原因 |
|---|---|
| 继续找 `.com` 的请求上下文（worker / webRequest 等） | 需要扩展新权限并依赖站内实现细节；已四次误判，收益不确定 |
| 解析结果页 DOM | 字段少（无 UT、无引证数），且依赖渲染结构，长列表可能只渲染可见部分 |
| 把 JCR 表打进发行包 | 授权不允许，且体积与年更都不合适 |
| 新增 `download` 动词 | 动词集封闭需 ADR，而这里没有新增能力的必要 |
| 让默认主机留在镜像站 | 非机构 IP 下镜像站无路由，等于放弃这条渠道 |

## 代价（明确记录）

- 每次检索 **8 个网络动作**（捕获路径是 4 个），因为导出要四次点击。
- 该路径**不支持翻页**：`page > 1` 直接拒绝并提示用 `exclude_ut` 走深。
- 影响因子依赖本地库；未导入时字段为 `null`，**不是 0**。
