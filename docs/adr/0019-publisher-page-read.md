# 0019 · 页面通读：AI 自己打开出版社页面（精选域名 + 只 goto）

**状态**：已接受并实现（2026-11-18）
**相关**：ADR 0002（只读）、ADR 0004（遇阻即停）、ADR 0005（配额）、ADR 0018（`snapshot` 动词）

## 背景

ADR 0018 交付的 `snapshot` 只保存**用户已经打开**的标签页。实际使用时这是短板：用户要的是
「给一篇文献，AI 自己去把网页打开、读完、回答问题」，而不是每次先由人点开页面。

要做到这一点，扩展必须能导航到出版社站点；而 0018 与 ADR 0002/0004 的地基是「只读知网与
WoS 两个域名」。这是一次边界变更，必须显式决策。

风险点很具体：在用户已登录的浏览器里自动访问出版社，多数站点的 robots/ToS 不欢迎自动化，
且容易触发人机验证。因此本次决策的核心不是"能不能"，而是"用多大的口子换多少能力"。

## 决定

1. **精选域名清单**（`core/publishers.py`）：25 家出版社/平台，每家一条 `{名称, 域名, 首页, DOI 前缀}`。
   清单之外一律返回 `unsupported_site`，**不尝试**访问。
2. **只 `goto`，不点不填**：`page_read` 只用 `goto`（首页 → 文章页）与 `snapshot`，不 click/type/select。
   撞上验证页立即以 `blocked`/`RISK_CAPTCHA` 结束，不重试、不刷新、不点。
3. **先首页后文章**：两次导航，形成正常的 referrer 链，而不是一步深链。
4. **DOI 解引用**：DOI 先经 `https://doi.org/<doi>` 解析（该解析器只把请求转到清单内的域名），
   也可以直接给文章 URL；两条路径都计入配额。
5. **计费**：`page_read` = **2 配额单位**（两次导航），`snapshot` 仍为 0。沿用 3 秒间隔与每日 300 上限。
6. **必须给出明确结论**：`status` 为 `ok` / `no_html`（`reason` ∈ `paywall`/`abstract_only`/`pdf_only`/`unparsable`）
   / `unsupported_site` / `blocked`；`no_html` 时尽量带 `pdf_url`，让调用方转 PDF 路线，而不是把摘要当全文。

## 被否的替代方案

- **任意 https 域名**：能力最大，但等于取消「只读两个渠道」这条地基，风控与合规无法评估。否决。
- **让用户手动打开、再 `snapshot`**（ADR 0018 的现状）：零新增风险，但不满足"AI 自己读"的目标。
  **保留为兜底**：`snapshot` 仍在，`page_read` 失败时可退回人工路径。
- **Python 侧自己发 HTTP 抓页面**：拿不到登录态、无 JS 渲染，且属于自建爬虫，风险更高。否决。
- **在新标签页里操作**（`tabs.create`）：多一个窗口干扰用户，且不改变风控基本面。否决。

## 后果

- 扩展的导航范围从 4 个域名扩到「4 + 25 家出版社 + doi.org」；内核与宿主两处白名单同步
  （`adapters/bridge/policy.py` 的 `TRUSTED_DOMAINS` 引用同一份清单，避免两边漂移）。
- 新增第 7 个 MCP 工具 `page_read`，`schemas/tools.json` 由生成器重建。
- 判定"页面里有没有全文"由 `core/pageprobe.py` 完成：数 `section[@id]`/`section-title`，配合
  付费墙标记词；解析不出来按 `no_html` 处理，**宁可说没有，也不把预览页当正文**。
- 该能力的合规责任落在使用者身上：访问哪个域、什么时候、访问了什么，都写审计；清单外站点不会被尝。
