# wensu 0.14.30 导航抓取与并发隔离评估

**结论：0.14.30 的真实握手和前置能力门通过，ACS 文章实际读取成功；但本轮发现 MDPI 文献身份误判和 ACS Markdown 正文大量缺失。当前适合串行网页访问、并行本地处理，不适合直接开启多标签页并行检索。共享锁能防止本插件计划同时操作浏览器，但尚缺相同任务合并、不可变快照及足够严格的文章身份校验。**

日期：2026-11-26，北京时间。仓库基线 `49701fd`，发布版本 `0.14.30`。没有修改产品实现或公开发布私有补丁；新增的是验收脚本与本报告。

## 安装与实际运行版本

从官方索引安装 0.14.30 到新版本 venv，并更新全局 CLI、DSH bundle、扩展文件及 native host 注册。配置、扩展备份在新版安装目录的 `upgrade-backups\20261126-191301`。用户确认重载扩展；保留原 profile、配额和冷却，原有私有补丁在两个安装环境的自检通过。

正式 MCP 接口的真实 status 回包包含：

  "worker": "background-0.14.30.js",
  "handshake": "ok",
  "host_version": "0.14.30",
  "capabilities": ["goto", "snapshot", "sleep"],
  "channel_capabilities": ["read_html", "read_text", "scroll", "click", "type", "select", "wait_for"]

上述 worker 字段位于 `status.browser_profile.bridge_build`。独立 MCP 客户端握手同为 0.14.30；没有使用本聊天残留的旧 MCP 做新版页面测试。除私有覆盖点 `core/page_nav.py` 外，安装包与仓库 52 个 Python 文件归一化换行后完全一致。

`scripts/release-check.py` 十门全通过：版本、schema、CHANGELOG、测试、lint、格式、类型、两层计划、资源及发行物。能力门另用真实 host 验证：page:mdpi 计划包含 goto/wait_for，返回 `action.unsupported`；执行包装器接收动作数 **0**、配额增量 **0**。包装器自身禁止发送动作，即使门失效也不会再误发导航。

## 真实文章与自然中间页信号

| 样本 | 实际结果 | 耗时 | 配额 |
|---|---|---:|---:|
| MDPI `10.3390/s26041303` | `no_page/capture_mismatch`，没有保存成成功结果 | 12.856 s | 2 |
| ACS `10.1021/acs.inorgchem.1c03019` | `ok`、`full_text=true`，快照 3,989,140 B | 10.922 s | 2 |

本轮真实额度 **271 → 267**，只做两篇各一次访问，没有重试 MDPI，没有并行站点压力测试。

ACS 的两条导航返回中，私有补丁的首页导航自然带有“请稍候”标题信号，文章导航标题正常，最终捕获到正文。没有返回 blocked，因此没有人工验证、重试或清理风控状态。

证据边界：这证明“首页出现中间页标题信号，后续文章访问成功”。不能扩大为“同一篇文章在墙上等待后自清”的验收，更不能声称已经自然遇到并正确处理持续真墙。为观测该信号，仅在测试入口给适配器加了被动结果记录，正式 MCP 工具、实际执行、节流和风控逻辑均未改动。

## 新发现一 文献引用被误当成本篇身份

**优先级 P1，真实页面与最小合成用例均复现。**

MDPI 的 final_url 与 captured_url 完全相同：`https://www.mdpi.com/1424-8220/26/4/1303`。返回的 declared_doi 却是一整段参考文献描述，含 Nano Letters 的另一 DOI。

原因位于 `core/pageprobe.py:145`：`meta_content` 判断的是目标字段名称是否出现在整个 meta 标签字符串内，而非 name 属性是否精确相等。MDPI 的 `citation_reference` 内容中也有 `citation_doi=…`，于是先被选中了。

最小复现结果：正确的 `<meta name="citation_doi">` 存在，但排在引用元数据之后；函数返回了引用内容，未返回本篇 DOI。

建议：只从主文档 head 中读取 name 属性完整匹配的元数据，单独处理 DOI 规范化。参考文献、相关文献与本篇元数据必须进入不同字段，不能由字符串包含关系决定文章身份。提示文案也不应仅凭此错误就断言“用户移动了标签页”。

## 新发现二 读取成功但转换丢失正文

**优先级 P1，安装版真实 ACS 产物复现。**

| 指标 | 结果 |
|---|---:|
| 源 MHTML 分类器的长段落正文词数 | 3,626 |
| 真实 citation_doi | `10.1021/acs.inorgchem.1c03019` |
| MCP 回报 Markdown 正文字节 | 1,564 |
| 实际 page.md 文件字节 | 1,572，含标题等额外内容 |
| Markdown 空白分词数 | 222，包含图注等 |
| 章节索引 | 仅 Supporting Information，4 tokens |
| 主体章节提取内容 | 44 B |
| 引擎 | sections，trafilatura_missing=true |

Markdown 中只有 Supporting Information 和 Figures 等，没有源文件的大量正文。告警只提到一处 MathJax 图形公式，未报告正文大量丢失。

这是官方默认依赖安装形态，没有额外安装可选 trafilatura。本轮没有临时补装它来把问题隐藏成通过。

建议：默认提取器提供不依赖出版社分节容器的正文退路，或者明确声明所需依赖与降级能力。转换结果增加源正文量、提取正文量和覆盖异常状态；正文远少于捕获内容时应返回可编程降级信号，不能只用 status=ok 交给下游生成结论。

## 当前导航和抓取会不会被视为爬虫

**仍有这种可能，现有客户端测试无法给出“不会被识别”的保证。** 当前没有站点侧检测日志，本轮也没有进行阈值探测。Cloudflare 的官方说明表明，检测会结合请求特征、会话和浏览器信号及行为模型，而不只依据是否使用真实浏览器或某一个访问间隔。[Cloudflare 检测机制](https://developers.cloudflare.com/bots/concepts/bot-detection-engines/)

### 需要区分三种动作

| 动作 | 站点侧与客户端含义 |
|---|---|
| goto、站内提交、刷新 | 能产生文档请求、重定向及后续资源请求；内核一个动作不等于一个 HTTP 请求 |
| snapshot | 当前实现调用 pageCapture 序列化指定标签；扩展快照分支没有单独的站点 fetch 循环，但网页自身仍可能继续加载资源 |
| 本地 MHTML 解析、索引和文本导出 | 解析器在本地工作，可离线并行；若随后用阅读器打开含远程图片的 Markdown，是否另发请求取决于阅读器设置 |

Chrome 将 `saveAsMHTML` 定义为把指定标签内容保存为 MHTML；这个接口的存在并不能证明整个页面生命周期没有网络流量。[Chrome pageCapture](https://developer.chrome.com/docs/extensions/reference/api/pageCapture)

### 当前实现的暴露点

1. **配额是动作配额。** `NETWORK_VERBS` 计 goto/type/click/select，无法统计一页自动触发的所有图片、脚本、接口和重定向。900 ms/150 ms 等是项目动作规则，不能解释为网站认可的安全频率。
2. **私有补丁增加首页访问。** 本轮每篇实际有两条内核 goto。没有做统计对照证明它减少验证；不能把它作为增加并发的依据。报告不包含其私有代码或首页表。
3. **扩展存在隐藏的内部尝试。** 被拒的 tabs.update 会再尝试，未进入 http 页面时还可能新建标签；内核仍只看一条 goto。未证明本次产生了重复 HTTP，但现有审计不足以证明没有，应回传尝试次数、最终 tab id 及导航是否实际发出。
4. **强制刷新会放弃浏览器缓存。** reload 分支使用 bypassCache=true；在没有明确需要重新获取时，应避免以强刷替代读现有快照。
5. **超时不等于撤销。** host 等待超时后移除 pending，扩展端异步动作没有与之配套的取消确认。静态审计提示晚到动作可能干扰下一任务，不能超时后立即默认标签页已经空闲。
6. **出版社响应的可见性有限。** 本轮出版社 goto 回包的 HTTP status 与 captcha_visible 均为空，内容脚本没有注入这些域。不能把“没有上报信号”解释为“站点没有拒绝”；需要明确未知状态与内容分类的证据范围。

建议把资源节约和清晰停止作为目标：合并重复任务、复用可验证缓存、减少不必要导航、单队列串行访问、自然遇阻立即停止。不要通过真实站点并发压测寻找“恰好不被检测”的访问方式。

## 多标签并行是否安全

**当前代码与 AGENTS.md 的 concurrency=1 不支持多任务同时自动检索。多个标签页可以同时保留，自动网络计划应排队。** 扩展有一个共享 workTab 和 boundTabId；给模型同时开放多个任务不会自动得到独立浏览器会话。

### 离线并发测试

使用安装版锁和策略、合成页面、临时状态，不连接真实 host：

| 场景 | 结果 | 解释 |
|---|---|---|
| 两线程使用同一个运行目录锁 | 临界区最大同时进入数 1 | 正常共享目录能串行化 |
| 两线程使用两个运行目录锁 | 最大同时进入数 2 | 如果它们指向同一个浏览器，目录隔离并不能提供浏览器隔离 |
| 同 DOI 两请求同时缓存未命中 | 两个都返回成功、都非 cached、各计费 2，合计 4 | 后到请求拿锁后没有再次检查缓存，产生排队后的重复访问 |
| 同 URL 和标题先后写两个快照 | 路径相同，旧路径读到新字节 | 文件路径不是不可变的文献版本凭证 |

这些是特定离线 interleaving 测试，不是对真实站点并发施压，也没有证明所有跨进程和其他扩展场景都已覆盖。

### 推荐执行模型

```mermaid
flowchart LR
    A[多个检索与阅读请求] --> B[任务去重与持久队列]
    B --> C[单个浏览器网络执行者]
    C --> D[身份绑定的不可变快照]
    D --> E[并行本地提取与分析]
    E --> F[身份和覆盖率校验]
    F --> G[按任务归集结果]
```

网络部分只保留一个执行者；多个文献的本地提取、索引、比对和写作可以在文件冻结后并行。普通任务不要自行创建不同 SCHOLAR_SEARCH_HOME 来共享同一个浏览器；所有访问入口仍需受统一的配额、冷却和排队控制。

如果业务确实需要程序化在线并行，应使用有明确授权与配额的接口，并遵守对应套餐限额。例如 WoS API Expanded 提供正式程序化访问，其许可及请求额度依机构合同配置。[Clarivate API 说明](https://developer.clarivate.com/apis/wos)

## 检索 多文献访问和数据传递如何隔离

### 任务调度

- 每个请求有 request_id、job_id、状态和明确取消阶段；相同 DOI/URL、相同视图和访问范围的请求合并到一个进行中的任务。
- 进入浏览器锁后再次检查缓存。先处理这处小改动，就能避免本轮已复现的双重缓存未命中导致的重复访问。
- 队列归属于实际浏览器资源和统一策略，不归属于任意一个调用方的临时目录。批量详情也由此队列分发。
- 超时任务的标签页进入“结果未定”状态，直到同一请求有终结证据；不把延迟回包交给下一文献。

### 标签和文章身份

- 网络任务获得 tab 租约，所有动作显式携带 tab_id 与 navigation_id。已有跨进程锁继续保留；不能依赖 activeTab 作为自动任务的归属。
- 捕获时核对请求、实际标签、捕获地址和主文档 DOI；明确缺少证据时的返回，而不是靠出版社域名猜“就是这篇”。
- **同出版社不等于同文献。** 安装版辅助函数仍接受同一 Wiley 域上的另一篇文章且没有 DOI 元数据的情形。离线调用 `_page_capture_belongs` 返回 true。
- **最后两个域名标签不等于机构边界。** 同一函数将 `unrelated.edu.cn` 与 `whxb.pku.edu.cn` 的末两段都解释为 edu.cn，判为同机构。这影响捕获归属，导航仍另受白名单约束。建议用策划的明确镜像映射，或正确处理公共后缀后再附加文章身份校验。

### 文件和消息

- 捕获写入以 capture_id/内容哈希区分的新目录，完成后原子发布；刷新产生新版本，不覆盖其他任务仍在读取的旧路径。
- 转换输出绑定 capture_sha256 和 extractor_revision。不同任务可以引用同一个不可变输入，但各自的草稿、筛选结果和临时文件有独立 job_id。
- 消息至少包含 schema_version、job_id、doc_id、requested_doi、declared_doi、captured_url、capture_sha256、判定依据及状态。搜索行、主文档元数据与参考文献分开存放。
- 下游使用 doc_id/哈希关联数据，不依赖数组顺序、简称、最后活跃标签或同名文件；保存参数投影和来源，避免把本地筛选结果当站点总数。
- 增加提取覆盖率检查。本轮 ACS 就说明：请求成功、快照成功和转换状态成功，也不能替代“正文确实传到了分析阶段”的证据。

## 改进顺序与验收

1. **先恢复内容正确性。** 修复 meta name 完整匹配和 ACS 正文提取退路；对包含 citation_reference 的真实结构与无标准分节容器的合成结构做回放，检查身份和正文保留。
2. **减少重复访问。** 缓存进入锁后再查一次，引入进行中任务合并。验收同 DOI 两请求只执行一组网络计划，两个调用方取得同一 capture_id。
3. **冻结数据再并行。** 将快照改为不可变版本，转换绑定哈希；验收一个任务刷新时，另一个任务仍读到原来的字节。
4. **补齐浏览器归属。** tab/navigation 租约、正确机构映射、超时终结状态和尝试次数。用假浏览器重放用户换页、另一扩展换页、延迟回包和取消，不用站点压力测试。
5. **保持网页网络并发为 1。** 并行度先放在离线处理；正式 API 的并行作为独立授权渠道设计。放宽当前硬约束需要新的 ADR，本轮没有实施这种变更。
