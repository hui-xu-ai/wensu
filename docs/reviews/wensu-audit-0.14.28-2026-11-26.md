# wensu 0.14.28 安装测试审计与改进方案

**结论：更新后的知网、WoS、文章读取、Markdown 转换、缓存和 RIS 导出基本链路均通过真实浏览器验收。代码审计仍确认 8 项 P1、6 项 P2 问题；主要集中在资源文件边界、风控契约、页面身份、分支返回一致性和转换器状态管理。应先修这些边界，再扩展出版社适配。**

日期：2026-11-26，北京时间。仓库基线：`b0cdeab`，版本 `0.14.28`。本轮没有修改业务实现，没有提交、打 tag 或发布；只新增审计材料及测试脚本，并按用户要求更新本机安装。

## P1 问题

### F01 图片引用可以读取来源目录以外的文件

位置：`src/scholar_search/page2md.py:1011`。

**端到端复现**：把含图片引用的合成 HTML 交给 `convert`，来源目录之外的模拟私有文件被复制到输出 assets。`resolve()` 仅得到绝对路径，没有检查它是否仍位于允许目录。

影响前提是用户将不可信 HTML/MHTML 交给转换器。证据证明本地文件复制，未证明上传或网络外传。

建议：MHTML 只采用其内联资源；普通 HTML 的本地图像严格限制在显式资源根目录内，拒绝绝对路径、UNC、盘符及解析后越界路径。检查应发生在任何读取之前。

验收：越界、符号链接或 junction 指向目录外的资源均拒绝；正常根目录内资源仍能转换；日志不输出文件内容。

### F02 MHTML 资源文件名可以写出 assets 目录

位置：`page2md.py:981`、`:1004`。

**Windows 端到端复现**：合成 MHTML 的资源名称包含 Windows 路径分隔符，`convert` 在输出目录之外创建了测试文件。文件名取自 Content-Location，只按正斜杠分割，之后直接拼路径。

现代码在目标已存在时跳过写入，所以本证据是越界创建，不能夸大为任意覆盖或代码执行。

建议：资源使用内容哈希产生单一安全 basename，不用网页名称充当文件系统路径；写入前再校验解析后的目标确实位于 assets。

验收：Windows 分隔符、盘符、UNC、目录跳转及名称冲突均不影响边界。

### F03 RiskGuard 与硬约束不一致

位置：`src/scholar_search/core/risk.py:193`、`:244`、`:248`。

**离线复现**：明确的知网 `/verify/home` 返回无风险信号，且未记录该 URL 提示；登录地址与 `auth_required=true` 只记 note，也不停止。403 与 `captcha_visible=true` 仍返回正确风险信号。

这与当前 AGENTS.md 第 3 条及 ADR 0022 修订 1 的“验证地址和登录跳转立即终止、不冷却”冲突。代码、交接摘要和硬约束已经分叉。

建议：先恢复明确、可归属的信号契约。精确验证路径与实际登录跳转须停止；普通文章提到 login/captcha 的文字不能简单用子串判墙。误报修复应收紧证据归属，不应取消强制停止类别。

验收：以带后续动作的 Plan 测试，一旦检测信号，后续 adapter 调用次数为零；403/429 保留 24 小时冷却。

### F04 空域名交集被转换成默认白名单

位置：`native-host/main.py:161`，关联 `adapters/bridge/policy.py:64`。

**真实本地 socket 处理函数复现**：请求域名集合与可信域没有交集，收窄结果为 `()`，但 `effective or None` 把它变成“采用默认可信域”；请求被放行。

扩大范围仅在内置可信域中，不是允许任意互联网域名；复现使用合成 token 与假 host，没有操作真实浏览器。

建议：明确区分“未指定域名”和“指定后交集为空”。后者直接返回拒绝，不得使用真假值回退。

验收：测试必须走 TCP handler → BridgeHost → policy 的整条链，仅测试 narrow_domains 本身不足以发现该问题。

### F05 captured_url 只有回显没有身份裁决

位置：`core/service.py:1219`，关联 `_classify_saved` 调用。

**夹具复现**：请求 Wiley DOI，快照数据返回另一篇 ACS 页面，仍得到 `status=ok`、`full_text=true`。回包同时带有不一致的 requested DOI 与 captured_url。

锁只能减少本插件间的竞争，不能阻止人或其他扩展移动标签页。URL 字段增多不等于实现身份校验。

建议：导航、捕获返回稳定 tab id 与 navigation id；结合捕获 URL、页面 citation_doi 绑定文章身份。同出版社不同 DOI 也不能只凭同源放行。证据矛盾时返回可解释失败，不作为成功缓存。

验收：跨站、同站另一 DOI、捕获前用户换页均不能返回请求文章的全文成功。

### F06 open-tab 复用绕过正文分类

位置：`core/service.py:1049`、`:1059`。

**夹具复现**：已有 blocked 标记，当前标签 URL 含请求 DOI，但内容只是付费墙，仍返回 `source=open-tab`、`status=ok`、`full_text=true`。

页面身份成立只说明“是哪篇”，不说明“读到了多少”。本分支没有调用与导航路径相同的内容分类器。

建议：所有快照都经同一身份校验和内容分类；只把“无需导航”作为来源/费用差异，不直接作为成功依据。避免 DOI 子串被更长 DOI 或查询参数误命中。

验收：同 DOI 的摘要、付费墙、空壳不能返回 full_text=true；真正全文复用仍为零额度。

### F07 全文视图分支吞掉风控并漏报费用

位置：`core/service.py:903`、`:923`、`:1205`。

**夹具复现**：首次落地页为 paywall；`view=full` 第二次导航返回 403。内部已设置冷却，外部仍回答首次的 no_html/paywall；实际扣 2、报价 1。第二次遇挑战标题也出现报价 1、实扣 2。

原因：失败分支返回 None，风险类别及已执行动作一并丢失；只有成功跟随后才将 extra outcomes 合并到费用。

建议：RiskBlocked 向上传播；跟随结果无论成功失败，都保留动作账本和明确终态。正文不存在和风控终止必须分开表达。已经存在正文时，不因 view=full 无条件再次导航。

验收：全文视图的成功、无正文、403、验证码、动作错误分别覆盖；所有返回费用与共享 ledger 的本次增量一致。

### F08 出版社等待逻辑没有对应的内容脚本能力

位置：`core/service.py:873`；`extension/manifest.json:17`；`background-0.14.28.js:939`。

**静态确认与假浏览器支持**：`_waited_out_gate` 依赖内容脚本接收 `wait_for(meta[name=citation_doi])`，但 manifest 只给知网与 WoS 注入 actions.js，没有出版社域，也没有 scripting 动态注入链。模拟无接收端时动作失败。

本轮 MDPI 正常路径未触发该等待，不能把成功读 MDPI 当成等待功能已验收。交接文档也承认真实等待分支未命中。

建议：首先决定该等待是否符合“遇风控即停”。不要为了让等待工作而直接扩大全部站点权限。若仅需判定已取得的页面，采用已有快照做本地分类；任何新增浏览器读取能力都应先定义最小权限及明确的非风控前提。

验收：扩展实际 manifest 与 tool 能力联测；不能只让 FixtureAdapter 返回一个现实中不存在的 wait_for 成功。

## 对交接结论的修正

- T3 加锁和回显 captured_url 是进步，但 F05 证明身份校验仍未闭环，不能宣称串文问题已经全面消除。
- T4 增加判定指纹和 refresh 是有效改进，但 F13 说明缓存回复仍不完整；不是“没有做过缓存修复”。
- T6 对 MDPI 这篇正文形成了合理分节；对 ACS/Wiley 的共享容器修复不能由本次单站样本推导。
- P3-11 的正常读取报价在本次私有补丁形态正确：实际 2、回报 2；但 F07 证明失败分支仍对不上账。
- WoS total/fetched/returned/effective_sort 的本次真实回包符合新语义；旧报告的“把导出条数当站点 total”不能继续当作当前正常路径缺陷。
- 12 秒等待和 view=full 的实际出版社特殊分支仍需定向验收。当前证据不支持继续增加延时或重试来追求一次成功。

## 私有补丁安装维护

本报告不包含私有实现或首页表。原有安装脚本和自检通过，不代表统计上证实降低验证频率；本轮未进行这种会增加站点访问量的对照实验。

静态审计发现的安装维护风险：默认 python 不保证与 MCP 解释器相同；版本兼容只检查 0.14 前缀；首次创建的 official 备份可能跨升级残留；覆盖后自检失败没有原子恢复；自检只验证文件与计划形状，不验证整个风险和费用链。

这次安装显式指定了两个解释器；原有全局 official 备份先另存，再由刚升级的官方文件建立匹配 0.14.28 的回退副本。私有源目录、公开源码和发布包保持分离。

建议私有安装采用版本号、原文件哈希、解释器路径及事务备份共同约束；只有目标哈希匹配才应用，失败即回滚。其发布隔离检查应只证明私有文件不在公开发行物中，不将私有代码加入公开测试仓库。

## 分阶段改进方案

| 批次 | 范围 | 必须通过的验收 |
|---|---|---|
| A 安全边界 | F01–F04、F11、F12 | 读写均留在允许目录；空域名集合拒绝；明确风控后零后续动作；损坏配额不放行；无效令牌不启动认证服务 |
| B 页面结果 | F05–F08、F13 | 所有成功路径共同校验身份和正文；缓存/open-tab/全文视图字段一致；失败费用与 ledger 一致；扩展能力与计划一致 |
| C 转换器状态 | F09、F10 | 并发或顺序转换不串章节/公式/图像；不同 URL 同名图片不冲突；正文图像覆盖可以解释 |
| D 验收与部署 | F14、版本握手、平台回放 | 夹具与真实协议一致；新装机器及旧版升级均验证；握手报告正在运行的 MCP/host/worker 构建信息；缺能力在导航前拒绝 |

每批独立提交、独立回归，先保留现有正常路径，再补上异常不变量。不要把四批合并成一次 service.py 大改。
